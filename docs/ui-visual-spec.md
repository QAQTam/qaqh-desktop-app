# QAQH 桌面 UI 视觉优化 Spec

版本：1.5 · 日期：2026-10-09 · 状态：主界面设计语言已收敛

### 1.5 输入区对齐 Qoder（会话级 profile + 身份行）

- 目标：输入区同时回答「我现在在哪、用什么跑、上下文多满」，并让模型／端点切换就地完成。
- **profile 选择器（会话级，已接线）**：读 `session.meta` 的 `profile`，写 `session.set_profile { name }`；空 name = 清除选择、跟随全局 `active_profile`。daemon 只定向重载该会话（`AgentReloadConfig`），不动其他会话，也不写全局配置。宿主侧 `session.set_profile` 在 `SERVICE_METHODS` 白名单里、且**不在**会话豁免名单里，所以 `service_rpc` 会注入活动 seed（前端另传 seed 时以参数为准）。
- **生效时机是 turn 边界，不是 ack**：daemon 的 ack 只表示命令进了队，而 `meta.json` 写得比生效早。因此选择器一律**重读 `session.meta`**（`setSessionProfile` 之后与每次 `turn_finished`），不做乐观落库；菜单尾部一行说明「新配置在下一个回合开始时用」。
- **模型不是独立可写的会话字段**：模型是 profile 的属性，控件标签展示 `profile → model`，菜单列出 `ConfigDto.profiles` 名录；不提供「临时换模型 ID」的假入口。但 **model 只能从全局扁平值推**：`ConfigDto` 只下发活跃 profile 的 `model`，名录里其他 profile 不带自己的 model，`SessionMeta.model` 又是建会话那一刻的快照（`reload_config` 不回写）。所以「本会话选了非活跃 profile」时标签只显示 profile 名、菜单项标「该 profile 的模型名未公开」，不拿快照充数。
- **权限档位不进输入区**：`permission_level` 在 daemon 中只有全局一份（`apply_profile` 不覆盖它，`SessionMeta` 无该字段），就地切换会造成「以为只影响本会话」的误解。档位仍只在设置页改，经 `config.save` 单一写口。
- **身份行（输入区表面外下方，只读，已接线）**：当前会话工作区名（sessions 目录项的 `cwd`/`workspace_id` + `workspaceCatalog`，取不到就整项不摆，不说「未分组」）、本地或局域网（`daemon_lan_status`，开局读一次）、上下文百分比 + 进度条 + tok/s + 缓存命中 + 端点原生 usage 项。原先贴在表面内的 `.composer-metrics` 条并入这一行，输入表面内只剩写与发。注意它与工具栏「新建会话目标工作区」选择器语义不同（前者是当前会话，后者是待建目标），两者不合并。
- 沿用现有 token 与 popover 菜单模式，不新增模态。
- 待办：`ConfigDto.profiles` 暴露每个 profile 的 model／是否自带 key（P1，补齐上面那条标签）；git 分支 chip（P1，`git.branch` 已在宿主白名单，缺 DTO + 调用）；拖拽／粘贴附件与图片多模态（P2）。

### 1.4 工作区面板改为真实右栏（覆盖 1.3 的浮层方案）

- 工作区集合面板不再是浮在正文右上方的覆盖层，而是 `.session-column` 的第 2 列（真实分配宽度）。原因：覆盖层在窄窗口下会直接盖住消息；改成列后正文与输入区被推挤但永不被遮挡。
- 展开 320px（`--workspace-panel-width`），收起缩到胶囊本身宽度；正文与输入区同在第 1 列，因此始终等宽对齐。
- 工作区区域过窄（容器宽度 < 720px）时面板自动收起为胶囊条，仍占位、不覆盖消息；点胶囊仍可强制展开。
- 相应废弃 1.3 中「展开不改变正文或输入区宽度」「开合前后正文/输入边界变化不超过 2px」的验收口径。

### 1.3 当前决策（覆盖早期 session tabs 方案）

- 顶部胶囊为未来 Goal 保留，现阶段 JSX 注释、不渲染、不预留空白轨道。会话只从左侧 session list 切换；窄窗口也保留紧凑会话列表；创建入口移到侧栏，原有快捷键保留。
- 工作区集合面板占会话列右侧的真实列宽（不再是浮在正文上的覆盖层）：展开 320px，收起缩到胶囊本身宽度，正文与输入区始终同宽对齐；面板由通用工作区标题和可组合的信息分区构成，待办是首个分区，后续可加入当前工作区 Git 变更摘要。收起保留可键盘操作的胶囊入口，面板最多占可视区高度的 70%，内容超出时在面板内滚动。工作区区域过窄时自动收起为胶囊条（仍占位、不覆盖消息），点胶囊仍可强制展开。
- Markdown 以 [GitHub Primer 官方源码](https://github.com/primer/css/tree/main/src/markdown) 为单一排版来源，矩阵和来源映射见 [markdown-typography.md](markdown-typography.md)。中途与最终回答统一为 16px/24px，覆盖早期 14px/22.4px 和 16px/28px 方案。

### 1.2 设计语言修订（优先于下文首版材质和尺度描述）

- 方向：安静、精确的专业桌面工作台。正文阅读区与输入容器使用稳定实色；Mica 透显保留在外壳导航与顶部切换器，不用于输入框，不动画模糊半径。
- 圆角按语义定义：`--radius-control: 8px`、`--radius-panel: 12px`、`--radius-dialog: 16px`。`--radius-pill: 999px` 仅用于标签、滚动条和细长标记；真正的圆形状态点保留 50%。现有 `--r-*` 作为兼容别名。
- 间距共用 4/8/12/16/24/32px token。常规控件高 36px；常驻分栏不加阴影，浮层使用 `--shadow-soft` / `--shadow-panel`。
- 界面和中文正文使用无衬线字体，Cascadia Code 仅用于代码、路径、日志等技术内容。Markdown 排版以 §1.3 与独立矩阵为准；工具元信息不改动 Markdown 基准。
- 正文与输入框共享 760px 内容宽度及响应式侧边距；输入容器的 padding 不计入正文目标宽度。滚动区对称预留滚动条，避免有无滚动条时中轴偏移。
- 工作区集合面板占会话列右侧的独立列（`grid-template-columns: minmax(0, 1fr) auto`），宽度展开 320px、收起为胶囊宽度；开合只推挤正文与输入区（两者同在第 1 列，因此始终等宽），不覆盖消息。窄视口使用同一交互，不另切换成侧滑抽屉。
- 会话标签数量按切换器父容器实际可用宽度计算，而非整窗宽度；保留当前会话、更多入口和创建入口。仅在容器尺寸改变时测量，不在流式 token 更新时测量。
- 完成任务使用勾选和次级文字颜色，不对整行画删除线。移除逐条错峰入场动画，避免快照刷新造成重播。
- 动效使用语义 token：反馈 120ms、进入 160ms、常规 180ms、退出 140ms、布局 220ms，统一 `cubic-bezier(.2, 0, 0, 1)`。菜单/Toast 位移不超过 4px；列表选中项不缩放；不使用 `transition: all`。
- 减少动态效果模式取消空间过渡与循环动画。正文流式输出不新增逐字装饰动画、不改滚动跟随逻辑。
- 验收：`scripts/visual-capture.mjs` 包含主界面亮暗、集合面板开合、480–1920px、125%/150% CSS 缩放与减少动态效果夹具。检查右栏始终不与消息列重叠（面板左边界 ≥ 消息区右边界）、正文与输入框边界差不超过 2px、开合时消息列宽按右栏宽度变化、面板向下展开且页面无横向溢出、键盘可重新展开。浏览器夹具不等同于原生 Mica 或 Windows 系统 DPI 的真机验收。

本文件记录 QAQH 的视觉目标与验收边界。Tauri/Electron 桌面壳使用左侧全局导航、消息页工作区／会话栏、内容区顶部 session capsule；窄屏全局导航移到底部。未来 WinUI 由 XAML 呈现窗口、全局导航与 session list，WebView 承载会话正文和工具页面。尺寸、配色和动效需经真实页面截图与性能测试验证。

## 1. 目标、范围与优先级

目标：建立清晰统一的 UI 原语，把全局页面导航与会话切换分层；session tabs 保持主要的轻玻璃强调，Tauri 桌面壳可在原生 Mica 窗口底材上为导航与输入区使用克制的透显表层，同时保持高速流式文本、工作过程和最终回答的稳定呈现。

优先级：内容正确与交互可用 > 流式性能与 DOM 稳定 > 视觉一致性 > 装饰效果。

本次实施范围：应用壳、会话导航、正文排版、输入区、工作摘要、工具详情、审批／待办／设置的共同视觉原语、深浅主题、响应式与无障碍。

功能与数据契约沿用现有实现：会话创建／关闭／切换、草稿、快捷键、审批、设置保存、宿主连接与时间线归约。新增视觉不得改写后端状态，不根据文案猜测消息类型。

首版不包含：真实光学折射、鼠标跟随光效、持续动画背景、整屏模糊、Skills 商店等新工具业务及其后台数据契约、重做消息协议。全局导航与工具页框架属于当前 UI 壳范围。这里的 Liquid Glass 是视觉语言的近似实现，不承诺复制系统原生材质。

### 未来嵌入宿主的兼容约束

WinUI/XAML 的窗口和 sidebar/session list 集成由宿主团队协调，本轮不实现 WinUI 桥接。当前 Tauri/Web UI 提供独立应用壳；正文、工具时间线、审批、输入等内容组件不依赖自绘 sidebar。宽度、滚动和内容最大宽度以 WebView 自身视口为准；避免硬编码整窗 `100vw`、假定左侧没有宿主栏、或让正文绘制外层窗口边框。未来嵌入宿主时，由宿主承载导航与 session list，WebView 渲染选中的主内容，并另行定义主题与活动会话的消息契约。

规范用语：**必须**为验收条件；**建议**可在提供截图与理由后调整。遇到装饰与性能冲突时，降低装饰强度。

## 2. 已确定的设计方向

- 全局页面导航与 session 切换是两个层级：全局为「消息 / 工具 / 设置」，session tabs 表示具体会话。
- Tauri/Electron 桌面壳左侧显示全局导航；消息页在其右侧按 workspace 分组列出会话。内容区顶部的 capsule 保留为当前打开会话的快速切换入口。
- 顶部 capsule 先保持现有会话切换用途；后续可评估改为当前 todo／goal 进度展示，不与本轮侧栏同时改动。
- 窄屏把全局导航移至底部；消息侧栏暂不显示，避免挤压消息正文，顶部 capsule 仍然保留。
- WinUI/XAML 宿主未来可以同时提供全局导航与 session list；WebView 只展示宿主选中的内容，不绘制第二份外层导航。
- 正文用排版、留白和表面层级区分内容，模型回答不套大型卡片。
- Web 视觉夹具中，玻璃仅用于 session tabs 背后的轻量表面。Tauri 使用原生窗口 Mica 作底材，导航与输入区可透显 Mica；工具、设置、菜单、审批和工作区集合面板保持实色。这里的 CSS 半透明与 backdrop-filter 是 WebView 表层近似，不等同于给单个 HTML 元素施加系统 Mica。
- 工作期间展开当前过程；开始中途回复或最终回答时收起前一个工作段；后续工作进入新段。

早期概念稿「底部会话胶囊」作为 session tabs 的外观参考；本节的全局导航与 session tabs 分层方案为当前实现决策。会话行为以本 spec 和项目代码为准，概念稿中的示例文案、图标数量不构成功能要求。

## 3. 页面布局

### 3.1 桌面默认布局

```text
┌──────────────────────────────────────────────────────┐
│ QAQH / 当前会话标题                 窗口控制           │ 40px
├────────┬─────────────────────────────────────────────┤
│        │ 会话 A  会话 B  更多  ＋                       │ session tabs
│ 消息   ├─────────────────────────────────────────────┤
│ 工具   │                                             │
│ 设置   │              会话 / 工具内容                  │ 可滚动
│        │                                             │
│        │ 审批 → 思考栏 → 输入区                        │
└────────┴─────────────────────────────────────────────┘

窄屏：标题栏 / session tabs / 内容 / 输入区 / [消息  工具  设置]
```

桌面应用壳使用明确的布局：`titlebar / (global-nav + workspace)`；消息 workspace 内为 `workspace-session-sidebar + (session-capsule / minmax(0, 1fr) content)`，其中 content 这一列本身再分 `正文与输入区 + 工作区右栏`（右栏展开 320px、收起为胶囊宽度），工具页不显示消息侧栏。窄屏使用 `titlebar / workspace / bottom-global-nav`，并收起消息侧栏。视觉上导航悬浮时，布局上仍要预留真实高度。禁止用 fixed 导航覆盖输入框，再靠猜测 padding 修补。

以上是当前 Electron/Tauri Web 独立壳布局。未来 WinUI 宿主可由 XAML 承载左侧全局导航与 session list，WebView 只承载当前会话、工具面板和设置等主内容；宿主向 WebView 分配客户区，并通过稳定接口传递当前页面／会话。WebUI 不依赖 XAML 控件，独立运行时继续提供自己的导航与 session tabs。该集成需另行定义接口并验收。

| 项目 | 默认目标 |
| --- | --- |
| 标题栏 | 高 40px；右侧保留现有窗口控制宽度 |
| 正文内容列 | 最大宽 760px；宽屏仍居中 |
| 输入区内容列 | 最大宽 760px，与正文对齐 |
| 内容侧边距 | ≥1024px 窗口为 32px；640–1023px 为 24px；<640px 为 16px |
| 输入容器 | 单行最小高 64px；textarea 最大高 160px，之后内部滚动 |
| session tabs 与输入区 | session tabs 固定在内容区顶部，输入区固定在内容区底部 |
| 桌面全局导航 | 宽 64px，图标与短标签纵向排列 |
| 窄屏全局导航 | 底部 56px，加可用的 safe-area inset |
| session tabs | 顶部独立行；宽度随可用内容区收缩，保留「更多」菜单与创建入口 |
| 正文尾部留白 | 24px；回到底部按钮位于滚动区内，不遮输入区 |

消息区保持内容顺序：审批／待办 → 思考栏 → 输入容器。思考栏空闲时保留 28px 槽位以避免频繁布局跳动；槽位自身不占据额外焦点。session tabs 与全局导航分别占独立轨道，不覆盖输入区。

审批卡列表最大高 `min(240px, 30vh)`，超出内部滚动。低高度窗口中 textarea 最大高降至 96px，审批区域上限降至 20vh，仍能看见输入操作。

### 3.2 响应式

必须验证 1280×900、1024×768、800×600、640×480、480×640。窗口宽 480px 时所有主要操作仍可用；不在视觉阶段擅自提高宿主最小窗口尺寸。

- 窄屏：全局导航位于底部；顶部 session tabs 缩短，非当前会话进入「更多会话」。
- ≥640px：根据实际可用宽度展示最近访问会话，最多四个，其余放入菜单。
- 当前会话必须始终直接可见；隐藏／显示规则只由切换、创建、关闭、尺寸变化触发，不受 token 输出影响。
- 不允许页面级横向滚动。代码、表格、diff 可在各自容器横向滚动。
- 缩放 125%／150% 后输入、导航和窗口控制不重叠。

## 4. 设计 token

在 `src/styles/app.css` 的现有 `@layer tokens` 扩展，不创建第二套主题入口。`data-theme` 与媒体查询兜底值保持一致；现有 diff 状态 token 保留。

### 4.1 颜色与表面

以下为候选值；实测对比度不达标时，调整 token，不能逐组件补颜色。

| 语义 token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#F5F7FA` | `#13171D` | 页面底色 |
| `--surface` | `#FFFFFF` | `#1D232C` | 输入、面板 |
| `--surface-2` | `#EBEFF5` | `#27303B` | 悬停、次级区域 |
| `--text` | `#192334` | `#EDF2F8` | 主文字 |
| `--muted` | `#59677A` | `#A4B1C3` | 辅助文字 |
| `--border` | `#DCE3ED` | `#354252` | 普通边界 |
| `--border-strong` | `#B7C4D5` | `#53657C` | 强边界／控件 |
| `--accent` | `#2563EB` | `#8AB4FF` | 选中与主要动作 |
| `--ok` | `#167341` | `#75D9A1` | 完成 |
| `--warn` | `#925B0B` | `#F5C36D` | 等待 |
| `--err` | `#B42332` | `#FF9AA5` | 失败 |

增加 `--accent-soft`（accent 的 10%–14% 混色）、`--focus-ring`、`--surface-user`、`--surface-code`、`--shadow-panel`、`--shadow-glass`、`--glass-bg`、`--glass-border` 和 `--glass-blur`。语义色必须搭配文字或图标，不单靠颜色传递状态。

普通文本目标对比度 ≥4.5:1；大文字、控件边界和焦点指示目标 ≥3:1。玻璃上的文字以最不利背景验证。

### 4.2 排版、间距、圆角

| 原语 | 目标 |
| --- | --- |
| 字体 | 沿用系统字体栈与现有等宽字体；首版不加载网络字体 |
| 界面基础文字（`--fs-body`） | 16px / 1.75 |
| Markdown 正文（`--md-body-size`） | 16px / 1.5，详见 [官方来源与完整矩阵](markdown-typography.md) |
| UI 标签（`--fs-sm`） | 15px / 1.5；辅助文字（`--fs-xs`）14px / 1.5 |
| 用户文字／输入（`--fs-md`） | 16px / 1.65（composer 实测 22px） |
| 回答标题 | Primer H1–H6 比例 2 / 1.5 / 1.25 / 1 / .875 / .85em，行高 1.25 |
| 代码 | Primer 85%；代码块行高 1.45，pre 内 code 为 100%，禁止二次缩小 |
| 间距等级 | 4、8、12、16、24、32px |
| 圆角等级 | 小控件 8px；卡片/待办 12px；输入 16px；标签 999px |
| 图标 | 默认 16px；主要动作 20px；沿用 Lucide |
| 图标按钮 | 常规 32px；主要按钮和窄窗口操作目标 40–44px |

> 历史 UI 尺度不再决定 Markdown 字号。Markdown 单独消费 `--md-*` token，浏览器矩阵检查以 Primer 来源值为准。

避免所有表面同时使用阴影。正文没有阴影，普通卡片使用边框，浮层使用一档柔和阴影，胶囊使用专属轻阴影。

## 5. 玻璃材质与动画

### 5.1 材质档位

首版实现两档：`glass` 和 `solid`，作为视觉偏好存储。先确认现有设置 schema／宿主白名单是否支持，不能把未知配置键直接发送给 daemon；不支持时使用独立本地偏好存储并注明其作用域。

| 属性 | glass | solid |
| --- | --- | --- |
| 浅色底色 | 白色约 82% 不透明度 | `--surface` |
| 深色底色 | 深色表面约 90% 不透明度 | `--surface` |
| backdrop blur | 固定 12px；验证后允许降至 8px | none |
| saturation | 固定 125% | none |
| 边界 | 1px 细边界＋顶部静态 inset 高光 | 普通边界＋轻高光 |
| 阴影 | 浅色 `0 7px 24px rgb(23 43 77 / 8%)`；深色更暗 | 同层级，强度可降低 |

`backdrop-filter` 不支持时自动使用 solid。`forced-colors` 使用系统颜色并移除滤镜和阴影。减少动态效果设置负责关闭动画，不擅自把用户的减少动画偏好等同于减少透明度。

Web 首版只有顶部 session tabs 使用 backdrop blur。Tauri 壳另外允许导航栏与输入区透显原生窗口 Mica，需保持低强度、清晰可读，不能把它扩展到消息正文、工具、设置、菜单、审批面板或工作区集合面板。禁止正文 blur、嵌套 blur、SVG displacement、动态噪声、动画 blur 半径、持续渐变动画。

### 5.2 动画

- 悬停／按下：120ms；菜单与面板出现：160–180ms；选中态：180ms。
- 导航优先独立标签背景的 opacity 过渡。共享滑动选中块为可选增强，必须只在切换／resize 时测量，不每帧读取标签位置。
- 发送按钮可使用短暂 `scale(.97)`；禁止改变按钮占位尺寸。
- 工作段自动收起立即执行；手动折叠沿用已有短动画与卸载机制。
- `prefers-reduced-motion: reduce` 下关闭位移／缩放过渡，内容直接切换。
- 主题变化只让页面底色和主要稳定表面短暂交叉过渡；消息 token、工具进度、状态点不加入主题动画，也不触发全树重绘。
- 首次启动解析已保存主题时直接应用，不播放过渡，避免首帧闪烁后再变色。
- 菜单、标签按下态与面板出现使用短距离、低幅度的合成属性动画；不连续漂浮、不做弹簧回弹。工作区右栏是真实列，开合会改变正文列宽（这是预期），但正文与输入框始终等宽对齐。
- 不全局铺设 `will-change`；仅在确有测量收益的少量动画元素上使用，并及时释放。

## 6. 组件规格

### 6.1 统一 UI 原语

在 `src/ui/` 建立或复用 Button、IconButton、Surface、StatusBadge、Menu、Field、Dialog 的公共规则。原语优先统一样式、语义与焦点管理，不为每个小元素包装额外 DOM。

按钮只保留 primary、secondary、ghost、danger 四种语义；字段只保留 default、focus、invalid、disabled 四种主要状态。菜单、弹窗、tooltip 的间距和边界共用 token。必须保留现有表单提示、审批含义和危险操作文案。

| 状态 | 共同要求 |
| --- | --- |
| hover | 轻表面变化，不改变布局 |
| pressed | 稍加强表面或短 scale |
| focus-visible | 清晰 2px 焦点环，不用阴影替代 |
| disabled | 实际禁用＋可读的辅助说明；不能只降低透明度 |
| loading | 按钮宽度保持；忙碌状态有可访问名称 |
| error | 错误文字＋状态图标／边界，不只变红 |

### 6.2 顶部 session tabs

会话项：状态点、单行标题、选中表面。标签宽建议 120–180px，标题省略；完整标题可在 tooltip／菜单中查看。状态点沿用现有 store 判断，不新增脉冲或 token 驱动动画。

右侧固定「更多会话」和「新建」按钮。「更多」菜单列出全部会话，显示活动／未读／等待状态；关闭动作放在菜单行右侧及会话上下文菜单，保留 Ctrl/Cmd+W。不得在 `role=tab` 的交互元素内嵌另一个可聚焦关闭按钮。

使用 `role=tablist` / `role=tab` / `aria-selected`，选中项 tabindex=0，其他可见项=-1。左右键移动焦点，Home／End 定位，Enter／Space 激活；移焦不触发宿主切流。现有 Ctrl/Cmd+Tab、Ctrl/Cmd+1–9、Ctrl/Cmd+T/W 保留。隐藏会话依旧可通过菜单和现有快捷键访问。

选择、关闭、创建后焦点有明确去向：键盘导航保持导航焦点；关闭当前会话将焦点移到新的当前标签；发送消息保持输入焦点。禁用新建的现有条件不得因改造绕过。

### 6.3 输入与思考栏

输入容器为普通表面，1px 边框，20px 圆角。焦点时强化边框；不对整个容器做持续发光。主发送动作使用 accent；运行时取消动作有明确标签，沿用现有发送／取消规则。

表面内自上而下：附件 chip 行（有附件时）→ 文本域 → 动作行（左：附件 `+`、profile／模型选择器；右：发送／取消）。表面外下方是**只读身份行**：当前会话工作区、本地／局域网、上下文百分比 + 进度条 + tok/s。摆放与语义见 §1.5。

保留 Enter／Shift+Enter、IME 组合输入、草稿按会话保存、附件与发送阻塞原因等现有行为。§1.5 列出的 profile 选择器是**唯一**允许在视觉改造中改写的数据流（原型 → `session.set_profile`）；其余 composer 数据流仍不得改写。权限档位不在输入区出现。

思考栏固定 28px，高度不随文本变化。文字单行、截尾；退出思考／更换块按现有逻辑清理。高速思考不逐 token 触发屏幕阅读器播报：状态播报使用独立、低频的状态信息，可见文字不作为持续 live region。

### 6.4 会话与工作过程

- 用户问题：右侧轻表面气泡，最大正文列宽的 85%；长问题允许换行和选择复制。
- 模型回复：普通正文，不套气泡；中途回复和最终回答使用相同宽度和字号。
- 当前工作段：紧凑标题「正在工作」，下方工具行／思考详情按需展示。
- 回复边界：前段变为「已工作 · 时长」的一行摘要；后续工具建立新的工作段。
- 摘要必须在对应回复之前，事件顺序不调整；不能把旧工作搬到回复之后。
- 用户可展开已完成工作；token 更新、快照校正和后来工具不得重置这个展开态。
- 自动折叠只卸载该工作段详情；已有回复 Markdown 保持挂载与节点身份。
- 下一段 assistant 文本开始时，前一工作段使用约 140ms 的高度收缩＋淡出动画收起；动画后卸载工具详情。历史闭合段初次展示不播放回收动画；遵循减少动态效果偏好。
- 失败／中断显示独立状态文案。工具失败不伪装为成功完成。

识别边界：使用协议中的明确类型／渠道和 reducer 已归约的 Step／Turn。若协议没有直接表达 `assistant:chat`，保留当前 text-block 边界处理并记录映射；禁止通过回复文案或首个 token 猜“最终回答”。最终完成状态只来自权威事件。

工具行使用统一小图标、名称、简短参数和状态。长参数省略但可展开；输出、ANSI、diff 沿用局部滚动和虚拟化。不要为每次进度追加创建一个新卡片。

工具时间线只展示面向用户的结果，不渲染原始参数或工具收据：文件工具的对象绝对路径只放在卡片顶层，不另设路径结果块；展开后显示成功的权威 diff 或必要诊断，没有结果时不显示空折叠入口。不显示读取全文或 old/new 请求；exec 默认展开运行 progress，终态以 stdout/stderr 替换（不叠加），无终态输出时保留最后尾窗，无时序信息时分区而不伪造交织；todo 与 skills 只显示“已更新待办／已调用 skills／已读取 skills”等语义行。失败诊断与授权等待仍可显示。路径使用后端路径与明确 cwd，禁止借浏览器目录猜测。关闭工具详情后仍卸载子树。详见 [工具渲染审计](./tool-render-audit-2026-10-09.md)。

### 6.5 正文、浮层与辅助面板

代码块使用 `--surface-code`，边框与 12px 圆角；复制按钮固定在块头，不影响代码布局。表格使用轻行分隔，避免每个单元格重边框。列表缩进、引用线、链接和标题间距统一。

空会话仅显示简洁标题、说明和输入引导，避免大型插画增加首屏成本。离线／重连／不兼容状态保留明确操作；错误不可被玻璃层隐藏。

设置：桌面居中实色面板，最大宽 960px、最大高 `calc(100vh - 48px)`；窄窗口使用可滚动全宽面板，分区导航固定在滚动区顶部并随阅读位置更新当前分区。待办与审批复用 Surface／Field／Button，审批仍有独立的语义强调。菜单／弹窗支持 Esc、焦点恢复、边缘避让；模态弹窗需要焦点约束，非模态菜单不能误锁整页。

## 7. 渲染与性能约束

必须保留现有优化边界，详见 [streaming-performance.md](./streaming-performance.md)。

1. token／progress 更新不能让 App、TabBar、全部 SessionView 列表重新计算。
2. 列表保持稳定 key；沿用会话／工作分组，不为装饰恢复大型广域订阅。
3. 文本组件不在 live、intermediate、final 三套 JSX 分支间反复重挂。
4. 已闭合 Markdown 不重复解析；尾块继续使用稳定文本／净化 DOM patch。
5. 结构事件前提交缓冲、快照部分覆盖和隐藏窗口提交兜底必须保留。
6. 不在 Solid apply 回调中意外读取响应式依赖；测量与 observer 使用当前 Solid 2 生命周期约定。
7. 光效、tab 指示、tooltip 坐标不能绑定 token 长度。布局读取集中在切换／resize／settled 阶段，不交错逐项读写。
8. 历史窗口仍执行淘汰，折叠工具不保留巨大常驻 DOM；玻璃装饰不能增加按消息数量增长的合成层。

采用安装包内 `solid-js/skills/reactivity-diagnostics/SKILL.md` 和 `CHEATSHEET.md` 的当前 API。禁止套用 Solid 1 生命周期或 React 组件模板后未经验证直接接入。禁止关闭诊断或提高告警阈值以“通过验收”。

## 8. 样式库与依赖策略

首版使用现有 CSS layers、Solid 2 和 Lucide 实现原语，不引入整套组件库、动画库或 Liquid Glass 特效库。这样可以保留当前 DOM 和响应式边界。

外部模板可作为配色、比例和状态设计参考，不能整体迁入应用。若后续需要复杂无障碍原语库，实施者必须先核实其当前 Solid 2 RC 兼容性、授权与实际新增包体，再仅接入需要的组件。不得为了一个胶囊导航引入另一套框架运行时。

## 10. 验收清单

### 10.1 视觉与功能

必须保存至少：浅色默认、深色默认、glass／solid 对照、480px 窄窗口、正在思考、工具运行、中途回复后折叠、最终回答、长表格／代码／diff、审批、设置这几类截图。截图可复用一张覆盖多个状态；不得用概念图替代真实页面。

- 所有表面、按钮和字段使用共同 token，无明显重复的颜色／圆角体系。
- 全局页面导航与 session tabs 分工清楚，窗口控制和拖拽正常；窄屏底部导航不覆盖输入与审批。
- 长标题、20 个会话、无会话、离线／错误状态都有可用布局。
- 快捷键、IME、草稿、滚动停随／贴底、分页补偿、审批与设置保存无回归。
- 键盘能够完成导航、菜单与弹窗操作，关闭后焦点恢复；缩放和 forced-colors 可用。

### 10.2 性能与正确性

类型检查、单元测试、生产构建必须通过。新增测试针对新的状态边界和行为，不为纯配色写镜像测试。

沿用性能文档中的 `QAQH_ASSERT=1` 场景；增加真实全局导航、顶部 session tabs 和材质开关后重新测试。

| 检查 | 通过条件 |
| --- | --- |
| 300／900 合成 token/s | 零丢字、精确最终文字、旧回复节点不重建、旧工作保持折叠 |
| 浏览器／Solid 诊断 | 无新 warning／error；现有诊断门通过 |
| 60Hz 流式帧 | 同机相同条件重复三次，P95 目标 ≤20ms，最大 <50ms；异常需说明来源 |
| 视觉增量成本 | glass 与 solid 同机比较，P95 增量目标 ≤2ms；不达标先降低／取消 blur |
| 复杂表格 | 最终 200 数据行完整；保留自适应限频，不声称每帧都完成解析 |
| DOM／历史窗口 | token 次数不导致额外外壳节点增长；翻页淘汰仍回到 50 个回合＋合并 gap |
| GPU／高刷新率 | 在真实 WebView2 验证玻璃合成；120Hz 下单独记录，不能套用 60Hz 结果 |

60Hz 数字是目标与回归门，不是对所有机器的保证。当前基线为软件 headless Edge 的合成流；最终交付必须区分前端合成流、真实宿主流和 GPU 合成结果。冷启动与重 Markdown仍需独立报告，不能仅用普通段落结果宣称全场景流畅。

## 11. 后续模型的交付要求

实施者应先阅读本 spec、性能说明和当前 npm 内 Solid skill，检查工作区已有改动，然后按 P1–P5 实施。用户已授权这份设计方向，常规可逆实现无需再次询问风格；遇到明确业务行为变更再提出具体问题。

最终交付包含：实际代码、关键页面截图、性能报告、测试结果、对 spec 的偏离及原因。主要风险和未验证环境须明确说明。不要修改已通过的性能断言来掩盖失败，也不要将概念稿当作已实现功能。
